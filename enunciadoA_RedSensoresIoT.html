Enunciado A: Red de Sensores IoT para Agricultura Inteligente

Modela, implementa y prueba una red de sensores que monitorea cultivos. Aplica herencia, polimorfismo, encapsulamiento, abstracción y las cuatro relaciones UML (asociación, dependencia, agregación y composición) sobre listas int[] y ArrayList.

Java plano IntelliJ IDEA JUnit Git POO
01

Descripción del problema

Contexto y requerimientos funcionales

Una empresa agrícola despliega una red de sensores para monitorear cultivos. Cada nodo de la red contiene varios sensores de distinto tipo (temperatura, humedad, luminosidad). Los sensores generan lecturas periódicas que se almacenan para análisis posterior.

El centro de monitoreo debe poder consultar en tiempo real:

  • El promedio de temperatura por nodo.
  • Los sensores cuyas últimas lecturas están fuera de rango.
  • Los técnicos asignados a cada nodo.

Requerimientos funcionales

  1. Existen tres tipos de sensores: SensorTemperatura, SensorHumedad y SensorLuminosidad, todos heredan de una clase abstracta Sensor.
  2. Cada sensor genera lecturas con valor entero, unidad y timestamp.
  3. Un NodoIoT posee sensores (composición: si el nodo se destruye, los sensores también).
  4. Un CentroMonitoreo agrega varios nodos (agregación).
  5. Cada Lectura depende de un servicio ValidadorLectura para validarse.
  6. Un TecnicoMantenimiento se asocia a nodos que revisa (relación N:M).
  7. Cada sensor mantiene un historial de sus últimas N lecturas usando un int[] de capacidad fija (buffer circular).
  8. El centro de monitoreo gestiona sus nodos con ArrayList<NodoIoT>.
02

Relaciones UML obligatorias

Debes respetar el contrato de diseño dado por el docente

El docente ya entregó el diagrama UML final en docs/UML-final.md. Tu código debe respetar exactamente las clases, atributos, métodos y las cinco relaciones que se listan a continuación:

RelaciónClases involucradasCómo se implementa
HerenciaSensor → SensorTemperatura, SensorHumedad, SensorLuminosidadClase abstracta Sensor + @Override en subclases.
ComposiciónNodoIoT ◆— SensorLos sensores se instancian dentro de NodoIoT.agregarSensor(...).
AgregaciónCentroMonitoreo ◇— NodoIoTLos nodos se crean fuera y se registran con agregarNodo().
AsociaciónTecnicoMantenimiento — NodoIoT (N:M)Referencia por atributo ArrayList<NodoIoT>.
DependenciaLectura ⇢ ValidadorLecturaSe pasa como parámetro, no se guarda como atributo.
Contrato de diseño: no agregues ni elimines clases. Las firmas de los métodos ya están dadas en el código base; tu tarea es implementar sus cuerpos.
03

Qué debes implementar

Tareas concretas para la Sesión 2

Buffer circular en Sensor

Implementa registrarLectura(int) con int[] de capacidad fija y promedioUltimasLecturas(). Cuando el buffer se llena, sobrescribe la lectura más antigua.

Generación polimórfica de lecturas

En cada subclase de Sensor, implementa generarLectura() para producir un valor aleatorio, registrar y retornarlo. Implementa fueraDeRango(int) con el rango de cada sensor.

Composición en NodoIoT

En agregarSensor(String tipo, String id, int capacidad) crea el sensor del tipo indicado dentro del nodo y agrégalo a ArrayList<Sensor>. Implementa promedioTemperatura() y sensoresFueraDeRango().

Agregación en CentroMonitoreo

Implementa agregarNodo(NodoIoT) y reporteTemperaturas() usando ArrayList<NodoIoT>.

Asociación en TecnicoMantenimiento

Implementa asignarNodo(NodoIoT) guardando la referencia en ArrayList<NodoIoT>.

Dependencia en Lectura

Implementa esValida(String tipo, ValidadorLectura v) delegando la validación al servicio. Implementa también ValidadorLectura.esValida(tipo, valor).

⚠ No modifiques la carpeta test/. Contiene las pruebas JUnit que usarás para verificar tu implementación. Cualquier modificación anula el examen.
El proyecto compila desde el primer minuto. Los métodos con TODO retornan valores neutros (0, null, false, listas vacías), así que puedes compilar y ejecutar IntelliJ antes de empezar a programar.
04

Indicaciones de Git

Clona, ramifica, commitea y sube

1. Clonar el repositorio base

git clone <URL-del-repo-base> parcial-estructuras
cd parcial-estructuras

2. Crear tu rama personal

Reemplaza nombre-apellido por tu nombre real en minúsculas.

git checkout -b parcial/nombre-apellido

3. Verificar que compila antes de tocar código

Abre el proyecto en IntelliJ y ejecuta Build → Rebuild Project. Debe compilar sin errores desde el primer momento.

4. Commits atómicos sugeridos

# Al responder las preguntas de comprensión
git add docs/comprension.md
git commit -m "comprension: respondo preguntas del UML"

# Al implementar el buffer circular
git add src/sensores/Sensor.java
git commit -m "impl: buffer circular y promedio de lecturas"

# Al implementar la jerarquía de sensores
git add src/sensores/
git commit -m "impl: generarLectura y fueraDeRango en subclases"

# Al implementar composición, agregación, asociación y dependencia
git add src/red/ src/personas/ src/servicios/
git commit -m "impl: relaciones UML completas"

# Al terminar
git add .
git commit -m "impl: TODOs completados y tests pasando"

5. Subir tu rama

git push origin parcial/nombre-apellido

6. Entrega

Publica en el aula virtual el enlace a tu rama en el repositorio remoto antes del cierre de la sesión.

Buenas prácticas: commits pequeños y descriptivos; nunca subas la carpeta out/ ni archivos .class; no hagas force push.
05

Cómo ejecutar el proyecto

Desde la descarga hasta ver Main corriendo en IntelliJ
Paso 1
Clonar el repositorio

Usa el comando de la sección 04. Se creará la carpeta parcial-estructuras/ con todo el contenido.

Paso 2
Abrir en IntelliJ IDEA

File → Open… y selecciona la carpeta raíz del proyecto clonado (no un archivo). IntelliJ detectará la estructura.

Paso 3
Marcar src como Sources Root

Clic derecho sobre la carpeta src → Mark Directory as → Sources Root. La carpeta se pondrá azul.

Paso 4
Marcar test como Test Sources Root

Clic derecho sobre la carpeta test → Mark Directory as → Test Sources Root. La carpeta se pondrá verde.

Paso 5
Descargar el JAR de JUnit

Descarga junit-platform-console-standalone-1.10.2.jar desde repo1.maven.org y guárdalo en la carpeta lib/ del proyecto.

Paso 6
Agregar JUnit como librería

File → Project Structure → Libraries → + → Java y selecciona el JAR descargado. Verifica en Modules → Dependencies que aparezca asociado.

Paso 7
Recompilar el proyecto

Build → Rebuild Project. Debe terminar sin errores. Si hay errores, revisa los pasos 3, 4 y 6.

Paso 8
Ejecutar Main

Abre src/Main.java y haz clic en el triángulo verde junto a public static void main. Se abrirá la consola con la salida del programa.

Atajo alterno por terminal: si prefieres no usar IntelliJ, desde la raíz del proyecto puedes compilar con:
mkdir -p out
find src -name "*.java" > sources.txt
javac -d out @sources.txt
java -cp out Main
06

Cómo ejecutar las pruebas

Verifica tu implementación con los tests JUnit

Opción A · Desde IntelliJ (recomendado)

  1. En el panel de proyecto, expande la carpeta test/.
  2. Clic derecho sobre la carpeta test → Run 'All Tests'.
  3. IntelliJ abrirá la pestaña de resultados con un árbol de tests en verde (pasaron) o rojo (fallaron).
  4. Si un test falla, haz clic sobre él para ver el AssertionError con el detalle de qué se esperaba.
  5. Itera: implementa, corre los tests, corrige, vuelve a correr.
Objetivo: todos los tests deben quedar en verde antes del cierre de la sesión.

Opción B · Desde la terminal

# Compilar src y test juntos
mkdir -p out
find src test -name "*.java" > sources.txt
javac -cp lib/junit-platform-console-standalone-1.10.2.jar -d out @sources.txt

# Ejecutar los tests
java -jar lib/junit-platform-console-standalone-1.10.2.jar \
     --class-path out --scan-class-path

Qué evalúan los tests

Archivo de testQué verifica
SensorTest.javaBuffer circular, promedio, generarLectura() y fueraDeRango() en cada subclase, polimorfismo en arreglo.
NodoIoTTest.javaComposición de sensores, tipo inválido, promedio de temperatura, detección de fuera de rango.
CentroMonitoreoTest.javaAgregación de nodos y generación del reporte de temperaturas.
ValidadorLecturaTest.javaValidación de temperatura, humedad y luminosidad según rango.
LecturaTest.javaDependencia entre Lectura y ValidadorLectura.
Recuerda: los tests están diseñados para comprobar el comportamiento esperado de tu código. Si un test falla, el problema está en tu implementación, no en el test. No modifiques los tests.
